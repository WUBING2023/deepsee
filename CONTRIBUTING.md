# Contributing to DeepSee

[简体中文](CONTRIBUTING.zh-CN.md) · [Back to README](README.md)

DeepSee is a small integration project with a strict rule: a route must work in the real Harness before the UI calls it available. Contributions that preserve that honesty and keep the plugin lightweight are welcome.

## Development setup

Requirements:

- Node.js 24 or newer
- pnpm 11 or newer
- DeepSeek Harness `0.1.0-rc.6` for the tested integration path

```powershell
git clone https://github.com/WUBING2023/deepsee.git
cd deepsee
pnpm install
pnpm run typecheck
pnpm test
pnpm run build:plugin
```

To install the development build into isolated local profiles and open the Web UI:

```powershell
pnpm run install:plugin
pnpm run start:web
```

These development scripts use the repository-local `.dsh` directory. They do not need to overwrite a normal user installation.

## Find the right layer

| Change | Start here |
| --- | --- |
| Host tools, prompts, Workflow, Prime | `src/index.ts` |
| Model schema and query behavior | `src/model-registry.ts` |
| Harness/API route mapping | `src/subagent-router.ts` |
| Vision and OCR behavior | `src/vision.ts`, `src/vision-adapter.ts`, `src/ocr.ts` |
| Runtime detection and health | `scripts/runtime-discovery.mjs`, `scripts/runtime-health.mjs` |
| Sidebar UI | `host/client.js` |
| Same-origin API | `host/admin-server.mjs` |
| Install and ZIP recovery | `scripts/install-plugin.mjs`, `scripts/folder-install.mjs` |
| MinerU installation | `scripts/mineru-install-strategies.mjs`, `scripts/install-mineru-worker.mjs` |
| Update protocol | `scripts/update-policy.mjs`, `scripts/update-manager.mjs`, `scripts/update-worker.mjs` |

Read [Architecture](docs/ARCHITECTURE.md) before adding a provider or changing state boundaries.

## Verification expectations

Run the smallest relevant test while developing, then the full gate before opening a pull request:

```powershell
pnpm run typecheck
pnpm test
pnpm run build:plugin
```

Changes to installation, updates, runtime discovery, or provider routing should also be tested in both profiles:

```powershell
pnpm run install:plugin
pnpm run start:web
pnpm run start:headless
```

A new runtime adapter needs negative tests as well as a success test: missing command, logged-out state, unsupported model, disabled route, and adapter failure should remain understandable and safe.

## Project conventions

- Prefer Harness-native providers, settings, subagents, and Workflow primitives over parallel infrastructure.
- Never mark a discovery-only runtime as executable.
- Do not expose raw credentials, credential references, or executable paths through the browser API.
- Keep mutable state under `$DSH_HOME/deepsee`; do not write it into package directories.
- Preserve `opends-*` / `OPENDS_*` compatibility identifiers unless the change includes a tested migration.
- `host/codex-provider.js` is generated by `pnpm run build:plugin`; update its source path and rebuild instead of making an isolated generated-file edit.
- Keep user-facing copy short. Put operational detail in the relevant guide rather than expanding the main README.

## Pull requests

A focused pull request should explain:

1. the user-visible problem;
2. the chosen behavior and compatibility impact;
3. how it was tested in Web and/or Headless;
4. any new state, environment variables, network sources, or secret boundaries;
5. screenshots for visible UI changes, with private model and account data removed.

Do not include API keys or subscription tokens in commits, fixtures, logs, screenshots, or issue reports.
