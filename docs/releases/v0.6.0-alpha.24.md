# DeepSee 0.6.0-alpha.24

DeepSee now separates installed, authenticated, image-capable, and actually routable Runtime states instead of treating them as one flag.

## Highlights

- Pass Harness image blocks directly into Codex App Server and Claude Code's native stream-json transport.
- Verify model-specific Claude vision with a small cached image probe; unsupported account/model combinations remain usable for text but stay out of the visual-reader list.
- Verify Gemini with a real headless authenticated request, so an installed but signed-out CLI can no longer be enabled.
- Apply model/OCR visual-reader preferences to new requests immediately and show the selected OCR engine honestly in the composer notice.
- Put DeepSeek first, keep healthy providers next, and move unavailable Runtimes to the bottom.
- Reject and migrate placeholder capability profiles such as `能力1 / 能力2 / 能力3`.

## Verification

- Codex `gpt-5.6-sol` accepted the same App Server data-image payload used by the plugin and correctly described the DeepSee panel screenshot.
- The current Claude subscription aliases returned `[Unsupported Image]`; DeepSee therefore keeps those models available for text/code while excluding them from vision routing until a future probe succeeds.
- Full type, test, package, site, installed-plugin, and browser verification completed on Windows with DeepSeek Harness `0.1.0-rc.6`.
