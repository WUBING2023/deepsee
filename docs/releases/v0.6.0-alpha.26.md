# DeepSee 0.6.0-alpha.26

DeepSee now keeps browser state, subscription runtimes, and OCR image turns on one consistent execution path.

## Highlights

- Use the shared Harness home by default for Web and Headless startup; isolated development state is now explicit.
- Preserve image-derived observations inside the original `tool-result`, preventing OpenAI-compatible `tool_calls` / `tool_call_id` transcript failures.
- Fall back from an unavailable selected OCR to another ready OCR or a verified visual model.
- Use the live Harness initiator when a subscription base-model request omits a session id, allowing Codex and Claude Code routes to behave like selectable base models.
- Identify the actual primary model in visual notices instead of always saying DeepSeek continues the answer.
- Explain OCR cold-start time and capability limits, and expose concise redacted installation diagnostics directly in the panel.
- Keep the OCR limitation hint to one native-style secondary line, with the full explanation available on hover instead of expanding the settings row.
- Force the local OCR protocol to UTF-8 on Windows so multilingual recognition cannot fail during output serialization.

## Verification

- PaddleOCR read the reported 2560×2048 Harness screenshot and returned the visible `insufficient tool messages following tool_calls` error through the normalized DeepSee protocol.
- Codex subscription model `gpt-5.6-sol` received the same image directly, identified the Harness interface, and explained the same tool-message-chain failure.
- Regression coverage validates nested tool results, OCR fallback, missing-session subscription routing, startup-home separation, diagnostics redaction, and Windows UTF-8 output.
