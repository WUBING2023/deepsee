# DeepSee 0.6.0-alpha.22 Verification Evidence

Verified on Windows with DeepSeek Harness `0.1.0-rc.6`.

## Runtime installer contract

- The model-directory header exposes a compact `+` action rather than another settings section.
- Gemini CLI can be selected even when it is not currently present on the machine.
- The install path must be absolute, cannot be a filesystem or state root, and must be empty or already owned by the same DeepSee Runtime.
- Installation runs in a detached background worker and reports phase, progress, strategy, and concise errors through the same-origin API.
- npm uses an isolated `--prefix`; the fallback downloads the `gemini.js` asset from the latest official `google-gemini/gemini-cli` GitHub Release.
- The resulting entry is validated with `gemini --version` before it becomes discoverable.

## Routing contract

- Gemini CLI uses the official headless JSON output contract.
- The dedicated provider forwards the selected Auto, Pro, Flash, or Flash-Lite model.
- A verified Gemini route can become the base model or a Workflow child after Harness restart.
- The Runtime group and source cell retain the stable `Gemini CLI` label while individual rows display Auto, Pro, Flash, or Flash-Lite.
- Authentication failures retain a direct `gemini auth login` hint.
- Local development installation uses the DSH remove/add refresh path, preventing version-only cache hits from omitting newly added files.
